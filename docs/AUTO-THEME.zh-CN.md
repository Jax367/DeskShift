# 覆盖期间自动加载标题栏主题（试验）

完整执行顺序、背景生成方法与验证范围见 [具体实现过程](IMPLEMENTATION.zh-CN.md)。

当前版已实施 [输入、主题文件和本机连接安全加固](SECURITY.zh-CN.md)。升级扩展目录和剩余限制请以该文档为准。

此功能默认关闭。软件中的「切换设置 → 浏览器标题栏 · 试验」提供自动加载总开关以及 Edge、Chrome 两个独立开关，可以同时开启。旧版的单浏览器选择会保留，两个开关都关闭时不会尝试加载。

开启前，每种目标浏览器都需要已有开发者模式、各只打开一个窗口，并使用 Default 配置。其他配置和多个窗口会停止或跳过该浏览器的加载。全屏过渡也必须开启，且系统允许动画。

应用壁纸时，软件先完成全屏覆盖，再依次打开临时标签页核对浏览器配置、进入扩展页并加载纯配色主题，最后提交 Windows 配色设置与桌面壁纸。此次调整避免 Windows 主题流程先改变焦点。确认主题目录已登记后关闭临时页并恢复焦点；目录登记不代表顶部标签栏已经渲染成新颜色。浏览器背景与桌面壁纸的清晰度策略保持不变。

自动化不开放远程调试端口、不写浏览器 Preferences、不使用剪贴板或全局输入监听、不自动开启开发者模式。只有固定颜色字段、有效 RGB 和没有运行时权限的主题可以加载。每种配色使用独立主题目录，避免旧缓存。

系统拒绝焦点切换、用户输入、未知控件、窗口变化或超时会停止自动化。单浏览器尝试最多约 7 秒，两浏览器共享约 9 秒预算；过渡本身仍有 12 秒保护。两个浏览器依次执行，不争抢焦点。未打开的浏览器会跳过；如果第一个留下临时页、未知文件选择框或检测到用户输入，则停止后续浏览器。设置页保留各浏览器的加载结果。失败时可能留下临时页面或文件选择框，用户可以手动关闭。为避免错误操作，取消后不会继续发送关闭窗口的按键。

此前独立 Edge 测试的实际结果：Windows 拒绝后台测试程序取得浏览器焦点，保护机制停止加载。该次测试未验证完整加载流程成功；不能视为稳定功能。普通软件自检与主题验证用于确认默认关闭、无覆盖时跳过、拒绝带权限的主题及无效 RGB，并不证明浏览器加载成功。

2026-10-11 用户实测：关闭所有 Edge 窗口后重新打开，顶部标签栏配色生效。这说明重开浏览器的路径在该用户环境中有效；是否所有后台进程退出尚未核实，也不能据此判断过渡期间的自动加载已经成功。后续可以单独研究在下一次正常启动时应用配色，避免为了配色强制关闭正在使用的浏览器。

2026-10-11 Chrome 排查：用户已选择 Chrome，但其主题记录仍指向项目的 `browser/chrome` 旧目录，而 Edge 指向 `browser-themes/edge/current`。Chrome 尚未启用新导出的主题，单纯重启不能把它换成新目录。独立 Chrome 测试也因 Windows 拒绝后台测试程序获取焦点而停止；本次双浏览器和执行顺序调整不能视为 Chrome 实机成功。必要时先使用软件的 Chrome 标题栏配色指南加载正确目录，避免把新标签页扩展目录当成主题目录。

## 回退

关闭「自动加载主题」即可恢复原有切换流程。退出试验版后，可启动原版本 `dist-dark-browser/DeskShift.exe`。

实施前的源码、原发布版、DeskShift 设置和导出的主题已保存在项目的 `backups/before-auto-theme-20261011-011131/` 中。该目录只保存在本机，不包含在发布压缩包中。备份里的 `release/DeskShift.exe` 是本次试验前的可运行版本。
